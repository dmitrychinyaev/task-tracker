# Глобальные правила Cline

## 1. Источники правды (Обязательно к прочтению)
Перед началом любой задачи ты ОБЯЗАН прочитать следующие файлы в корне проекта, чтобы понять архитектуру и правила:
- `spec.md` (поведение продукта)
- `project_context.md` (доменный контекст)
- `README.md` (как запускать)
- `rules.md` (инженерные ограничения)

## 2. Правила ведения тикетов (Ticket Tracking)
После успешного выполнения любой задачи по написанию или изменению кода, ты ОБЯЗАН:
1. Запросить у пользователя номер тикета (если он не известен).
2. Создать файл в папке `docs/tickets/{НОМЕР_ТИКЕТА}.md` (или обновить существующий).
3. Записать в него: что было изменено, какие файлы затронуты, были ли миграции.
4. Сообщить пользователю, что тикет сохранен.

## 3. Запреты
- Не удаляй и не переписывай файлы без явного указания.
- Не добавляй новые зависимости без согласования.
